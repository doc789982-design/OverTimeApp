# Переезд интерфейса на веб-технологии

Решение: переводим интерфейс OVERTIMETAB с QML на HTML/CSS постепенно
(«удушение по частям»): Python-ядро не трогаем вообще, умирает только
слой отображения. Движок (database.py, logic.py, utils.py, export.py)
остаётся единственным источником правды — веб-интерфейс лишь разговаривает
с ним через локальный API.

## Принципы

1. **Данные и расчёты — только через движок.** Ни одной формулы в JS.
   Веб-слой вызывает те же функции, что и QML-слой.
2. **QML-версия работает, пока веб не догонит.** Каждый этап живёт в
   webapp/, релизы программы продолжают собираться из QML. Переключение
   главного интерфейса — только после прохождения «этапа-приёмки».
3. **Реальная база — только по явному флагу.** Пока этап не закрыт,
   сервер веб-версии открывает демо-базу. Реальная база подключается
   ключом `--db путь` или переменной OVERTIMETAB_DB.
4. **Каждая правка reversibel: transaction() в движке автоматически
   делает снапшот, отмена (undo) доступна всегда (Ctrl+Z).**

## Этапы

### Этап 1 — главный экран: чтение + правка дня ✅ (закрыт)
- [x] Список сотрудников (поиск, группы, бар нормы)
      (мини-год в карточках убран по решению пользователя — не нужен)
- [x] Календарь месяца (дежурства, статусы, праздники, предпраздничные,
      компенсации, сегодня)
- [x] Панель балансов (карточки, скобки прошлого года, одометр)
- [x] Вид «Год» (панорама 12 месяцев + суммы по месяцам)
- [x] Инспектор дня: статусы К/Б/О, удаление дежурств,
      добавление дежурства (валидация пересечений), отмена (undo)
- [x] Тёмная/светлая темы, кнопка «Сегодня», тосты
- [x] Редактирование существующего дежурства: времена, тип,
      комментарий, перерывы (несколько, через полночь) — порт
      updateDuty из Main.py, пересечения проверяются с исключением себя

### Этап 2 — полный учёт
- Диалог дежурства: правка, перерывы (несколько), интервалы через полночь
- Компенсации: ДВО/сверх нормы (часы), ДДО (дни), панель «Деньги»
- Карточка сотрудника: создание, правка, вводные остатки
- Группы: создание, перенос сотрудников (drag&drop), смещённые выходные
- Производственный календарь: ручные дни (работа/выходной/праздник)

### Этап 3 — вывод и настройки
- Экспорт Excel (пачками и по сотрудникам), экспорт Word
- Печать (тот же движок)
- Настройки программы, обновления, «Что нового»
- Undo/redo панель, горячие клавиши (полный паритет)

### Этап 4 — оболочка (превращение в «программу»)
- Встройка в существующее приложение: окно pywebview (Edge WebView2)
  или QtWebEngine — решается на месте по размеру установщика
- Иконка, автообновления, ассоциации — всё существующее остаётся
- Режим «оба интерфейса»: веб-вид по кнопке из QML-версии

### Этап 5 — переключение и вычистка
- Веб-вид становится главным, QML — запасным (одна сборка)
- Удаление QML-слоя, облегчение установщика

## Приёмка каждого этапа
1. Все сценарии из QML-версии повторяются в вебе тем же движком.
2. Прогон на копии реальной базы (пользователь решает сам).
3. Параллельная эксплуатация одну-две недели.

## Текущее состояние
- `webapp/server.py` — API поверх движка (чтение: bootstrap/month/year/day;
  правки: duty/add, duty/update, duty/delete, day/set-status, undo)
- `webapp/static/` — интерфейс (index.html, app.css, app.js)
- Запуск: `python3 webapp/server.py` → http://localhost:8081
- Реальная база: `python3 webapp/server.py --db путь/к/базе.db`
- Из сборки программы: кнопка «Веб-версия» в окне справки
  (запускает второй процесс с --web и текущей базой — самый простой путь)
- Ярлыком: `OVERTIMETAB.exe --web` (база из настроек, или `--db путь`);
  флаг прощает опечатки: «--web.», «--WEB», «/web» тоже работают
