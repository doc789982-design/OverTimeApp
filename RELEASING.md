# Как выпускать сборку OVERTIMETAB

Инструкция для того, кто сопровождает проект — человека или ИИ. Она
писана так, чтобы её хватило без всякой дополнительной памяти: просто
следуйте шагам. История сборок (что въехало в какую сборку) — в
BUILD_HISTORY.md, она генерируется из коммитов git.

## Из чего состоит релиз

**Релиз = два обязательных файла, оба собирает CI автоматически:**

| Файл | Кто скачивает | Зачем |
|---|---|---|
| `OVERTIMETAB_<версия>_<sha>.exe` | человек | Установщик: двойной клик → мастер установки. Устроен как «заглушка + этот же zip» |
| `OVERTIMETAB_<версия>_<sha>.zip` | установленная программа | Автообновление: программа ищет на релизе файл с `.zip` на конце и качает его |

**Убирать exe с релиза нельзя** (человеку нечего скачивать), **убирать
zip нельзя** (старым установленным программам нечем обновляться — они
физически не умеют читать релиз без zip). Публиковать релиз вручную
командой `gh release …` тоже не нужно — всё делает скрипт ниже, он сам
проверит оба файла и откажется работать, если чего-то нет.

## Шаги (по порядку)

1. **Код готов.** В `components/AppTheme.qml` поднимите `appBuild` до
   следующего номера, в `CHANGELOG.md` добавьте запись в раздел текущей
   версии и обязательно пометьте её номером сборки: `<!--b:243-->` —
   без пометки окно «Что нового» её не покажет. Запись пишется простым
   языком по правилам из начала CHANGELOG.md (без программистских
   терминов, одно–три предложения): публикатор проверяет стиль сам и
   откажется выпускать сборку с кривой записью.

2. **Коммит и пуш** рабочей ветки.

3. **Карта сборок.** `python3 tools/build_history.py --write --tag`,
   закоммитьте обновлённые `BUILD_HISTORY.md` и `CHANGELOG.md`
   («История сборок: N»). Публикатор откажется работать, если текущей
   сборки нет в карте.

4. **QA-батарея** — все тесты из `qa/` должны быть зелёными
   (переменные окружения песочницы — в шапке любого теста).

5. **Публикация.** `python3 tools/publish_release.py --tag v2.0.0-ALPHA.20`
   (тег — постоянный, номер версии в нём не меняется). Скрипт сам:
   создаст/обновит релиз, **дождётся сборки Windows**, **проверит, что
   на релизе есть и zip, и exe** с текущим sha, снимет старые ассеты.
   Если сборка сломалась или файлов нет — он упадёт с ошибкой, и релиз
   надо чинить, а не обходить проверку.

6. **version.json.** Впишите в `updates/version.json` поля:
   `version` «2.0.0-ALPHA.<N>», `build` N, `display` «BETA.1»,
   `url` — **имя архива** `OVERTIMETAB_BETA.1_<sha7>.zip` (НЕ полный
   адрес — это правило проекта, адрес склеивается с хранилищем).
   Коммит «version.json: имя архива сборки N» и пуш.

7. **Заголовок и заметки релиза**: `gh release edit v2.0.0-ALPHA.20
   --title "OVERTIMETAB BETA.1 · сборка N" --notes-file <notes>`; заметки —
   `changelog_section("BETA.1")` из `tools/publish_release.py`.
   Первая строка заметок должна подсказывать человеку качать **.exe**.

## Почему так (кратко)

- Установщик — стандартный **Inno Setup** (`tools/overtimetab.iss`):
  привычные окна «Далее → папка → установка», как у любой программы.
  CI ставит Inno через chocolatey и собирает `iscc`-ом из той же папки
  `dist\OVERTIMETAB`, из которой делается zip, — программа в обоих
  файлах побайтово одна и та же.
- Установленная программа ищет на релизе файл с `.zip` на конце (это
  зашито во все выпущенные сборки), поэтому zip обязан остаться рядом
  с exe.
- При установке поверх прежней Inno помнит прежнюю папку; при
  удалении спрашивает, удалять ли данные сотрудников
  (`Документы\OverTimeTab`), — по умолчанию они остаются.

## Готовые проверки (qa/)

- `qa/test_release_gates.py` — воркфлоу собирает zip и exe, публикатор
  требует оба, RELEASING.md на месте. Если тест красный — кто-то
  сломал релизную цепочку, чините, а не удаляйте тест.
- `qa/test_changelog_style.py` — правила журнала описаны в шапке,
  все записи им соответствуют, нарушения ловятся, публикация блокируется.
- `qa/test_installer.py` — скрипт Inno Setup: ключевые директивы,
  источник файлов, вопрос про данные при удалении; проверяет также,
  что самописный мастер старых сборок не вернулся.
